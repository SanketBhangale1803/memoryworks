# T-003: Situation report endpoint, and routing in Ask, Agent, and MCP

- **Status:** open, depends on T-001
- **Pillar:** Situation (`VISION.md` §1). This task passes the north-star test.

## Problem
"What are the issues in the system?" goes to passage retrieval and gets back documents. A deterministic lane for live-state questions already exists for connections (`retrieval/service.py` about line 217, `is_connection_question`). Situation questions need the same treatment.

## Outcome
1. `GET /api/situation?project_id=&service=` returns open Issues ranked by severity × recency × blast radius. Blast radius comes from `DEPENDS_ON` edges and `orgops.find_blockers`. Each Issue includes its evidence links, owner, `first_seen`, what it blocks, and **the linked memories that explain it**. The response has a `summary` line, and returns `no_signals` (distinct from "healthy") when no signal source is connected.
2. Ask routing: situation questions ("what are the issues", "what's broken", "is X healthy", "what's failing", "anything on fire") go to this lane, with `answer_scope="situation"`. Use explicit, inspectable vocabulary, as `_STATUS_QUESTION` does. Wording comes from a template, with no LLM in the data path. A model may *phrase* the result only when one is configured.
3. Agent mode: a read-only tool `get_situation` in `frontend/lib/orgTools.ts`, registered in `hooks/useWorkspaceTools.ts`.
4. MCP: `get_orgmemory_situation` in `mcp_server/server.py`, with a test next to `mcp_server/tests/test_preflight_tools.py`.
5. Briefings: `POST /api/briefings` adds an `active_issues` group listing open Issues on the named service. An open Issue on the target raises the verdict to at least `proceed_with_context`.
6. Watches: add `issues` to `orgops/watch.py` `CHECKS`, so new Issues reach a person without anyone asking.

## Acceptance
- Ask "What are the issues in the system?" against a fixture workspace with two CI failures and one sync error. The answer lists exactly those three, ranked, with sources, in under 2 seconds without an LLM.
- Ask against a workspace with no signal sources. The answer says nothing is connected that could show live state. It does **not** say "no issues".
- A briefing test shows an open Issue raising the verdict.
- Backend, frontend, and MCP tests are green.
