# T-004: Dogfood eval. 40 real questions about this repo, scored in CI

- **Status:** open, no dependencies (can run in parallel with T-001)
- **Pillar:** Parity / eval (`VISION.md` §5)

## Problem
"Better than Glean" and "better than asking a coding agent" aren't measured. `docs/BENCHMARKS.md` and `docs/HCAG_BENCHMARK_PLAN.md` describe retrieval evaluation, but nothing in CI keeps answers honest.

## Outcome
1. `backend/evals/dogfood/questions.yaml`: 40 questions a real engineer on this repo would ask. Each one has gold facts (assertions, not prose), gold source paths, and a category: `ownership`, `decision`, `how-it-works`, `situation`, `history`, or `no-answer` (where the correct response is "memory doesn't know"). At least 5 questions are `no-answer`, and 5 are `situation` (fixture-backed, for T-003).
2. A runner that ingests this repository at a pinned commit into a fresh workspace (GRAPH_BACKEND=memory, no network), asks each question through `/api/ask`, and scores **fact recall**, **citation precision** (cited paths ⊆ gold paths), **abstention correctness**, and **p50/p95 latency**.
3. A CI job runs the deterministic subset (no LLM) and fails if any metric drops more than a set tolerance below the committed baseline (`baseline.json`).
4. The same harness can, separately, score a "cold coding agent" baseline from a recorded transcript file, so the comparison in `VISION.md` is a number.

## Constraints
- No network or LLM key in CI. LLM-dependent questions are marked and skipped there.
- Gold answers come from the code and docs **at the pinned commit**, with file:line evidence in the YAML.

## Acceptance
- `make eval-dogfood` prints a metrics table and writes `backend/evals/dogfood/last_run.json`.
- The CI job passes on `main` with the committed baseline.
